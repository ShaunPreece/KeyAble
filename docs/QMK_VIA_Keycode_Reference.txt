QMK / VIA KEYCODE REFERENCE
===========================
The keycodes and protocol commands KeyAble is built on. They are the standard
QMK and VIA ones, so this also applies to Keychron Launcher and the VIA
configurator.

This file covers:
  1. What the "Any" keycode field is and where to find it
  2. Modifier wrapper syntax
  3. Complete KC_ key name list
  4. Numeric keycode values (for VIA protocol CMD_SET_KEY)
  5. Special and media keys
  6. Limitations - what this syntax cannot do
  7. VIA protocol quick reference
  8. Authoritative sources


===========================================================================
SECTION 1 - THE "ANY" KEYCODE FIELD
===========================================================================

Both the Keychron Launcher and the VIA configurator (usevia.app) include a
field called "Any" (usually under Custom → Any in the keymap screen). It
lets you type a raw QMK keycode string instead of picking from the standard
key list.

The Keychron Launcher does NOT extend or modify QMK syntax - it uses the
same strings as VIA. Any valid QMK modifier-wrapped keycode string that works
in VIA will also work in the Keychron Launcher.

The VIA "Any" field accepts:
  - Plain key names:         KC_A, KC_F5, KC_DEL
  - Modifier-wrapped keys:   LSFT(KC_P), LCTL(LALT(KC_DEL))
  - Preset combinations:     HYPR(KC_T), MEH(KC_NO)

It does NOT accept:
  - Macro sequences (use the macro recorder instead)
  - Tap-dance or mod-tap keycodes
  - Layer-switching keycodes


===========================================================================
SECTION 2 - MODIFIER WRAPPER SYNTAX
===========================================================================

Wrap any KC_ key name in one or more modifier functions.

SINGLE MODIFIERS
----------------
  LSFT(kc)   or   S(kc)    Left Shift + key
  LCTL(kc)   or   C(kc)    Left Ctrl + key
  LALT(kc)   or   A(kc)    Left Alt + key
  LGUI(kc)   or   G(kc)    Left Win / Cmd + key

  RSFT(kc)                 Right Shift + key
  RCTL(kc)                 Right Ctrl + key
  RALT(kc)                 Right Alt + key  (also used for AltGr)
  RGUI(kc)                 Right Win / Cmd + key

The short aliases S(), C(), A(), G() are fully equivalent to LSFT(), LCTL(),
LALT(), LGUI() - use whichever is clearer.

COMBINING MULTIPLE MODIFIERS
-----------------------------
Nest the wrapper functions:

  LCTL(LALT(KC_DEL))          Ctrl + Alt + Delete
  LSFT(LGUI(KC_S))            Shift + Win + S  (Windows snip & sketch)
  LCTL(LSFT(KC_ESC))          Ctrl + Shift + Esc  (Task Manager)
  LCTL(LALT(LSFT(KC_P)))      Ctrl + Alt + Shift + P

Short alias versions of the same:
  C(A(KC_DEL))
  S(G(KC_S))
  C(S(KC_ESC))
  C(A(S(KC_P)))

PRESET MULTI-MODIFIER COMBINATIONS
------------------------------------
These are QMK shortcuts for common modifier bundles:

  LCA(kc)      Left Ctrl + Alt + key
  LCS(kc)      Left Ctrl + Shift + key
  LSA(kc)      Left Shift + Alt + key
  LCAG(kc)     Left Ctrl + Alt + GUI + key
  MEH(kc)      Left Ctrl + Shift + Alt + key     (all three, no GUI)
  HYPR(kc)     Left Ctrl + Shift + Alt + GUI     (all four modifiers)

MEH and HYPR are useful for creating shortcuts that no application uses by
default, so they will not conflict with anything. Assign MEH(KC_T) to a key
and set that shortcut in any app.

Using KC_NO as the base (modifier only, no letter):
  HYPR(KC_NO)   - sends all four modifiers held, no additional key
  MEH(KC_NO)    - sends Ctrl + Shift + Alt held, no additional key
These are used to make a physical key act as a pure modifier chord.

EXAMPLES
--------
  LSFT(KC_P)            Shift + P
  LCTL(KC_C)            Ctrl + C  (Copy)
  LCTL(KC_V)            Ctrl + V  (Paste)
  LCTL(KC_Z)            Ctrl + Z  (Undo)
  LGUI(KC_L)            Win + L   (Lock screen)
  LGUI(KC_D)            Win + D   (Show desktop)
  LGUI(KC_R)            Win + R   (Run dialog)
  LGUI(LSFT(KC_S))      Win + Shift + S  (Snip & Sketch)
  LALT(KC_F4)           Alt + F4  (Close window)
  LCTL(LALT(KC_DEL))    Ctrl + Alt + Delete
  LCTL(LSFT(KC_ESC))    Ctrl + Shift + Esc  (Task Manager)
  HYPR(KC_A)            Ctrl + Shift + Alt + GUI + A  (custom hotkey)
  MEH(KC_B)             Ctrl + Shift + Alt + B        (custom hotkey)

SECTION 4 - NUMERIC KEYCODE VALUES (FOR CMD_SET_KEY)

The VIA HID protocol's CMD_SET_KEY command (0x05) takes a 16-bit keycode
value. When you type a string like LSFT(KC_P) in VIA's Any field, VIA
converts it to a 16-bit number before sending it to the keyboard.

A remapper that talks to the keyboard directly, as KeyAble does, needs these
numeric values.

MODIFIER-WRAPPED KEYCODE ENCODING
----------------------------------
When you wrap a key in a modifier function, QMK encodes it as a 16-bit value
with the modifier bits in the upper byte and the basic keycode in the lower byte.

The upper-byte modifier bit positions:
  Bit 8  (0x0100)  =  Left Ctrl
  Bit 9  (0x0200)  =  Left Shift
  Bit 10 (0x0400)  =  Left Alt
  Bit 11 (0x0800)  =  Left GUI
  Bit 12 (0x1000)  =  Right-side modifier flag (OR'd with bits 8-11 for right variants)

Right-side modifiers:
  Right Ctrl  = 0x1100  (right flag 0x1000 | left-ctrl bit 0x0100)
  Right Shift = 0x1200  (right flag 0x1000 | left-shift bit 0x0200)
  Right Alt   = 0x1400  (right flag 0x1000 | left-alt bit 0x0400)
  Right GUI   = 0x1800  (right flag 0x1000 | left-gui bit 0x0800)

To calculate the 16-bit value for a modifier-wrapped keycode:
  combined_mods | basic_keycode

EXAMPLES:
  LSFT(KC_P)              = 0x0200 | 0x0013  = 0x0213
  LCTL(KC_C)              = 0x0100 | 0x0006  = 0x0106
  LCTL(LALT(KC_DEL))      = 0x0100 | 0x0400 | 0x004C  = 0x054C
  LCTL(LSFT(KC_ESC))      = 0x0100 | 0x0200 | 0x0029  = 0x0329
  LGUI(LSFT(KC_S))        = 0x0800 | 0x0200 | 0x0016  = 0x0A16
  HYPR(KC_A)              = 0x0100|0x0200|0x0400|0x0800 | 0x0004  = 0x0F04
  MEH(KC_A)               = 0x0100|0x0200|0x0400 | 0x0004  = 0x0704

Authoritative source for exact values: QMK firmware source file
  quantum/keycodes.h  (github.com/qmk/qmk_firmware)

For VIA-specific keycode parsing, see the VIA source:
  github.com/the-via/reader  (the library VIA uses to parse keycode strings)

SECTION 5 - SPECIAL AND MEDIA KEYS
===========================================================================

QMK defines consumer/media keycodes that send HID consumer page codes.
These work as standalone assignments (not inside modifier wrappers).

AUDIO / VOLUME
--------------
  KC_MUTE    Mute
  KC_VOLU    Volume Up
  KC_VOLD    Volume Down

MEDIA PLAYBACK
--------------
  KC_MPLY    Play / Pause
  KC_MSTP    Stop
  KC_MPRV    Previous track
  KC_MNXT    Next track
  KC_MFFD    Fast forward
  KC_MRWD    Rewind

BRIGHTNESS (on supported hardware)
------------------------------------
  KC_BRIU    Brightness Up
  KC_BRID    Brightness Down

KEYBOARD BACKLIGHT (QMK RGB/backlight control)
-----------------------------------------------
  RGB_TOG    Toggle RGB lighting on/off
  RGB_MOD    Cycle through RGB modes
  RGB_RMOD   Cycle RGB modes in reverse
  RGB_HUI    Hue increase
  RGB_HUD    Hue decrease
  RGB_SAI    Saturation increase
  RGB_SAD    Saturation decrease
  RGB_VAI    Value (brightness) increase
  RGB_VAD    Value decrease
  BL_TOGG    Toggle backlight
  BL_INC     Backlight brightness increase
  BL_DEC     Backlight brightness decrease

LAYER SWITCHING (VIA supports these in the standard picker, not "Any")
----------------------------------------------------------------------
  MO(n)      Momentary layer n (hold to activate)
  TG(n)      Toggle layer n on/off
  TO(n)      Switch to layer n (replaces current)
  DF(n)      Set layer n as default
  LT(n,kc)   Layer n when held, key kc when tapped  (mod-tap variant)

Note: Layer-switching keycodes have a separate VIA keycode encoding range
and are not typically entered via the "Any" field - use the layer picker.

TRANSPARENT / NO-OP
--------------------
  KC_TRNS    Transparent - falls through to the key definition on the layer below.
             Shown as a shaded key in VIA. Essential for multi-layer setups.
  KC_NO      No operation - key does nothing.


===========================================================================
SECTION 6 - LIMITATIONS
===========================================================================

THE 8-MODIFIER CONSTRAINT
--------------------------
The modifier wrapper syntax only works with the 8 USB HID hardware modifier keys:
  Left/Right - Shift, Ctrl, Alt, GUI (Win/Cmd)

It does NOT work with:
  CapsLock  - is a toggle key at the HID layer, not a held modifier
  Num Lock  - same, toggle only
  Fn        - firmware-only, not a USB HID keycode at all
  Any other "regular" key

You cannot create a shortcut like "CapsLock + S" using the Any field.
CapsLock is KC_CAPS = 0x0039, a regular keycode, not a modifier bit.

IMPLICATIONS FOR NVDA USERS
----------------------------
NVDA uses Insert (or optionally CapsLock) as its modifier key. NVDA intercepts
these at the OS level. The keyboard sends a plain KC_INS or KC_CAPS keycode;
NVDA detects it is held and watches for the next key.

You cannot encode "NVDA modifier + S" in a single keycode assignment, because:
  - There is no USB HID concept of "CapsLock held"
  - NVDA's modifier interception happens above the HID layer

WORKAROUND: Assign a shortcut that uses standard modifiers to a key (e.g.
Ctrl+Shift+Alt+S via MEH(KC_S)), then bind that shortcut inside NVDA's Input
Gestures dialog to the NVDA command you want. This is more reliable than
trying to simulate CapsLock/Insert behaviour.

SINGLE KEYCODE ONLY
---------------------
The VIA "Any" field and CMD_SET_KEY accept exactly one 16-bit keycode value
per key slot. You cannot assign a sequence of keypresses (e.g. type "hello")
to a key via this mechanism - that requires macros.

MACROS
------
VIA supports up to 16 macros (QMK firmware dependent). Macros can contain:
  - Key press/release sequences
  - Text strings (each character sent as a keypress)
  - Delays between steps
These are stored separately from the keymap and use the macro commands in
Section 7.

MOD-TAP (not available via "Any")
-----------------------------------
QMK supports keycodes like LCTL_T(KC_A) (Left Ctrl when held, A when tapped).
The VIA "Any" field does NOT support mod-tap syntax - these must be configured
in the firmware source or via QMK Configurator.

SECTION 7 - VIA PROTOCOL QUICK REFERENCE
===========================================================================

Keychron's QMK keyboards ship with VIA built in and always on (the factory
firmware is the "via" keymap build). They expose a raw HID interface:
  Usage page: 0xFF60
  Usage:      0x0061

Every message is a 32-byte report (report ID 0x00), zero-padded. The reply
echoes the command byte first. In WebHID: hidDevice.sendReport(0x00, bytes),
then match the 'inputreport' reply by its first byte, with a timeout in case
the device does not answer (wrong device, or firmware without VIA).

Commands KeyAble uses:
  0x01  get protocol version   handshake; confirms the keyboard answers VIA
  0x04  get keycode            [0x04, layer, row, col] -> bytes 4..5
  0x05  set keycode            [0x05, layer, row, col, kc_high, kc_low]
  0x06  dynamic keymap reset   rewrites every key with its firmware default,
                               effective immediately
  0x07  custom set value       lighting and other per-board values
  0x08  custom get value
  0x09  custom save            store custom values to EEPROM
  0x0C  macro get count        reply byte 1 = number of macro slots
  0x0D  macro get buffer size  reply bytes 1..2, big-endian
  0x0E  macro get buffer       [0x0E, offset_hi, offset_lo, size]
  0x0F  macro set buffer       [0x0F, offset_hi, offset_lo, size, data...]
  0x11  get layer count
  0x14  get encoder            [0x14, layer, encoder_id, clockwise]
  0x15  set encoder            [0x15, layer, encoder_id, clockwise, kc_high, kc_low]

Note 0x0A (EEPROM reset) only invalidates EEPROM until the next reboot; use
0x06 to restore factory keys immediately.

Example: remap row 0, col 0 on layer 0 to Ctrl+C (LCTL(KC_C) = 0x0106):
  [0x05, 0x00, 0x00, 0x00, 0x01, 0x06, 0, 0, ... (26 more zeros)]

Each key's (row, col) address comes from the board's VIA JSON layout, where a
key is written as "row, col" (e.g. "0, 5").
